# Neverquest 0.3.3

## Changes

- Vendor estimates now learn from all discovered local characters, without needing to select each character first. Connecting a character imports the other characters' Character and Social ledgers and archives under the same game-data folder.
- Other characters' ledgers are checked every ten seconds using cached readers. Their recorded sales contribute to vendor estimates throughout the app, including hunts, reports and overlays. Prices remain separate by server; player market listings remain separate from vendor estimates.
- Background imports preserve the selected character and hunt ownership, do not replay activity alerts, and retain saved history when source records rotate or become temporarily unreadable. Problems reading another character's ledger are reported with that character's name.

## Download and upgrade

Download **Neverquest-Setup-0.3.3.exe** and run it, or let an installed Windows build download the update and use **Update ready — Restart**. Updates also install when you quit after pending saves finish.

Windows x64 is supported. The installer remains unsigned, so Windows may show an Unknown publisher or SmartScreen warning. Existing history, hunts and preferences are preserved in `%APPDATA%\Neverquest`; collection format remains version 1.

## Verification

- All 102 automated tests passed locally, including discovery across characters, server isolation, archive/Social deduplication, hunt and report pricing, restart persistence, and recovery from incomplete ledger writes.
- JavaScript syntax, public-file and whitespace checks passed. Package and lockfile versions match 0.3.3.
- The release workflow builds the tagged source on Windows and runs source and packaged Electron smoke checks before creating a draft. Exact asset checksums are appended to the GitHub release notes.
- The runtime dependency audit reported no vulnerabilities. Build tooling retains the 15 moderate findings already recorded for 0.3.2; dependencies are unchanged.
- Clean-account installation, real installed-version update flows and in-game overlay interaction were not repeated for this patch. Local desktop smoke checks were not repeated; the release workflow supplies isolated Windows smoke checks.
